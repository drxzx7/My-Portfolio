Netflix Eureka Heartbeat & Lease Lifecycle Sequence

Chronological handshake protocol illustrating instance registration, heartbeat renewals, client delta caching, and automated eviction.

Protocol: Eureka REST API Lease Duration: 90 Seconds Heartbeat Interval: 30 Seconds
1
Instance Registration (At Service Boot)

Microservice initializes and sends POST /eureka/apps/{appName} carrying host IP, port, metadata, and status check URL (/actuator/health). Eureka adds instance to the read-write registry cache.

2
30-Second Heartbeat Lease Renewal

Every 30 seconds, the microservice dispatches PUT /eureka/apps/{appName}/{instanceId}. Eureka refreshes the 90-second expiration lease timestamp, confirming node viability.

3
Client-Side Delta Registry Synchronization

Microservices fetch incremental registry updates via GET /eureka/apps/delta every 30 seconds and cache it locally. Downstream RPC calls query the local memory cache directly, requiring zero network hops to Eureka for routing decisions.

4
Fault Eviction vs. Self-Preservation Mode

If Eureka misses 3 consecutive heartbeats (90 seconds) from an instance, the background eviction task removes it from the routing table. However, if renewal counts fall below 85% cluster-wide due to network jitter, Eureka activates Self-Preservation Mode to protect healthy instances from false deregistration.
